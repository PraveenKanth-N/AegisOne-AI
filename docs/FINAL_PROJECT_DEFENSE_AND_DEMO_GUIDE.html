Problem 1: Raw CVSS Severity Trap

Traditional tools (SonarQube, Burp) rank bugs solely by theoretical CVSS score. An SQL injection in an internal demo script gets flagged with the same panic as one in an internet-facing user database, leading to developer alert fatigue.

✔ Solution: Security Knowledge Graph & Contextual Risk Engine

AegisOne correlates static code taint sinks with runtime network exposure and data sensitivity to calculate true contextual business risk.

Problem 2: Unchecked AI Code Regressions

Generative AI (ChatGPT/Copilot) produces "plausible" fixes that hallucinate syntax errors, break API contracts, or inadvertently disable authentication routines.

✔ Solution: 4-Stage Isolated Docker Sandbox Validation

Patches run in disposable containers tested across Syntax, Regression, AST Taint, and Security Rescan. Flawed fixes are automatically rejected.

✔ Solution: Hardened Scope Guard Whitelist Boundary

Architectural interceptor strictly enforces zero external network calls; only pre-approved localhost/lab endpoints are permitted.

Problem 4: Unverifiable Compliance Logs

Audit trails in traditional DevOps are easily modified or forged, making zero-trust compliance audits (OWASP/PCI-DSS) unreliable.

2. How the Cybersecurity Mechanism Works (Step-by-Step)

AegisOne AI unifies Static Application Security Testing (SAST), Dynamic Application Security Testing (DAST), and Graph Theory:

Mechanism How It Works Technically Why It Is Defensible in Review
1. AST Taint Tracing (SAST) Parses code into an Abstract Syntax Tree (AST). Traces user-controlled input (Source: request.args.get('id')) to execution without sanitization (Sink: cursor.execute(...)). Proves deterministic evidence. We pinpoint the exact file (app.py) and line number (Line 42) where unsanitized data reaches SQL engine.
2. Active Fuzzing (DAST) Dispatches non-destructive HTTP payloads (e.g. ' OR '1'='1) against the running local lab (:8001) to verify live response behavior. Eliminates false alarms by proving the vulnerability is actively exploitable over HTTP, not just dormant code.
3. Knowledge Graph Linkage Constructs directed graph linking Endpoint → Taint Sink → Database Entity → CWE Definition → OWASP Category → CISA KEV Exploits. Calculates contextual risk using Dijkstra reachability and centrality metrics rather than static CVSS numbers.
4. Closed-Loop Sandbox Validation Executes candidate patch in a disposable container through 4 rigorous gates: Syntax Check, Unit Tests, AST Taint Check, and Rescan. The Showstopper: Guarantees zero code regressions. If an AI patch causes a syntax error or contract violation, it is instantly rolled back.
5. Immutable Audit Chain Each event computes hash = SHA256(prev_hash + event_data + timestamp) signed with Ed25519 key. Provides non-repudiation. Reviewers can verify the mathematical validity of the audit chain with one click.

6. Viva & Review Defense Questions & Answers (Memorize These!)

Q1: "Why not just use SonarQube or standard static analysis tools?"

Answer: "SonarQube is a passive scanner that only checks code syntax and produces raw alert lists without understanding real runtime exposure or data sensitivity. More importantly, SonarQube cannot generate verified patches or test them in a live sandbox. AegisOne is an active, closed-loop copilot that detects, contextualizes with a Knowledge Graph, fixes, and sandbox-validates the patch."

Q2: "Why can't developers just copy-paste code into ChatGPT to fix vulnerabilities?"

Answer: "Studies show that over 40% of AI-generated code contains subtle bugs or security regressions. ChatGPT generates code that looks convincing, but it has no execution environment to verify if the fix broke existing application logic. AegisOne isolates the AI patch in a disposable container and runs unit regression tests and AST verification before allowing any merge."

Q3: "What is your main academic / research contribution?"

Answer: "Our research contribution is fourfold: (1) Graph-based contextual risk scoring combining SAST and DAST, (2) Evidence-grounded AI reasoning that eliminates hallucination, (3) A 4-stage containerized validation engine with automated contract-preserving rollback, and (4) An immutable SHA-256 hash-chained audit trail providing mathematical proof of compliance."

Q4: "What is Scope Guard and why is it necessary?"

Answer: "Scope Guard is an architectural security interceptor. When an AI agent or automated scanner runs, there is a risk it could send fuzzing payloads to public third-party APIs or unintended servers. Scope Guard strictly enforces a network whitelist—blocking all outbound requests except to approved localhost and test lab containers."

Q5: "How does the Knowledge Graph improve prioritization?"

Answer: "Standard CVSS assigns a score in isolation. Our Knowledge Graph connects code endpoints to data sensitivity (e.g. Student PII) and network exposure (e.g. Public vs Internal). An SQL injection on a public endpoint accessing private data receives a 92.1 score, while an injection on a local internal script receives lower priority. This eliminates developer alert fatigue."

Q6: "How do you prove your audit trail hasn't been tampered with?"

Answer: "We use a cryptographic hash chain similar to blockchain principles. Each event's hash is calculated using the previous event's hash: H_n = SHA256(H_{n-1} + Data_n). If anyone alters even a single character in past logs, the hash chain breaks immediately. Our /api/v1/audit/verify-chain endpoint mathematically validates the integrity of all blocks."
